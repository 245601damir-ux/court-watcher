# court-watcher

Раз в час проверяет свободные слоты на крытых кортах Academy Tennis Daulet (Altegio, филиал 521176) и шлёт в Telegram только **новые** слоты.

## 1. Узнать токен и id кортов (5 минут)

1. Открой страницу бронирования в Chrome → DevTools → вкладка **Network**, фильтр `alteg`.
2. Обнови страницу. Найди запрос вида `.../api/v1/book_staff/521176`.
3. Из него возьми:
   - домен (`https://api.alteg.io/api/v1` или другой, например `https://n12345.alteg.io/api/v1`) → `API_BASE`, если отличается;
   - заголовок `Authorization: Bearer XXXX` → `ALTEGIO_TOKEN` (если заголовка нет — оставь пустым);
   - в ответе список кортов (`id`, `name`) → id крытых в `STAFF_IDS`, например `123,456`.

Без `STAFF_IDS` скрипт ищет корты по словам в названии (`NAME_FILTER`, по умолчанию `крыт,indoor,хард`) и, если ничего не нашёл, печатает список всех кортов.

## 2. Telegram-бот

1. @BotFather → `/newbot` → получить токен → `TG_TOKEN`.
2. Написать боту любое сообщение, открыть `https://api.telegram.org/bot<TG_TOKEN>/getUpdates`, взять `chat.id` → `TG_CHAT_ID`.

## 3. Локальная проверка

Заполни `.env` (шаблон — `.env.example`) и запусти:

```bash
set -a; . ./.env; set +a
go run .
```
Без `TG_CHAT_ID` уведомление просто печатается в консоль — удобно смотреть формат.
`state.json` хранит уже отправленные слоты, удали его, чтобы получить всё заново.

### Корты этого филиала

Крытые корты называются «Корт 1»…«Корт 8», и слова «крыт» в имени у них **нет** —
признак `Крытый` лежит в поле `specialization`. Поэтому отбор идёт по имени *и*
специализации, а в `.env` на всякий случай прописаны явные id:

```
STAFF_IDS=1513587,1521552,1521553,1521555,1521557,1521558,1521559,1521561
```

Открытые корты — «Корт №1»…«Корт №5» (с решёткой), это другие id.

Сейчас включено отслеживание **всех** кортов: `NAME_FILTER=*`, `STAFF_IDS` пуст.
Так подхватятся и корты, которые клуб добавит позже.

Внимание на ловушку: слово `крыт` **входит внутрь** слова `открытый`
(о-т-**крыт**-ый), поэтому `NAME_FILTER` сравнивает по началу слова, а не
подстрокой — иначе фильтр крытых кортов захватывал бы и открытые.

### Крытые корты не продаются онлайн

В филиале всего две услуги в онлайн-продаже: «Аренда открытого корта (1 час)»
2500 ₸ и «Аренда стенки» 1000 ₸. Услуги аренды крытого корта **не существует**,
у крытых кортов привязано 0 услуг — поэтому `book_dates` по ним и пуст. Их,
видимо, берут по телефону (+7 706 641-04-85). Бот сработает, если клуб добавит
их в онлайн, но ждать этого можно долго.

### Почему тишина — это нормально

У крытых кортов бронь сейчас закрыта: `book_dates` отдаёт по ним пустой список.
Так и должно быть — бот ждёт, когда их откроют. Что он живой, видно в логах
Actions: там каждый час `кортов: 8, свободных слотов: 0`. Если токен перестанут
принимать, бот не промолчит, а пришлёт в Telegram алерт (один раз, не каждый час).

### Формат уведомления

Слоты группируются по дате и часу, а не по кортам:

```
🎾 Появились слоты (Крытый):
7 окт 19:00 — Корт 1, Корт 3
8 окт 06:00 — Корт 1
```

Так 197 слотов укладываются в 42 строки и влезают в лимит Telegram (4096 символов).

## 4. Запуск по расписанию

### Почему крон часовой, а проверка каждые 15 минут

Расписание Actions — best-effort: опоздавшие срабатывания **отбрасываются**, а не
встают в очередь. При `cron: "*/15"` окно между срабатываниями всего 15 минут,
поэтому GitHub съедал большую часть и фактический интервал выходил 27–60 минут
(замерено: 23 прогона за 23 часа вместо 92). Поэтому крон часовой, а 15-минутный
шаг делает цикл внутри прогона — на него throttling не влияет. Job живёт ~46 минут;
на публичном репозитории минуты Actions не лимитированы.

**GitHub Actions (бесплатно, без сервера):** запушь репозиторий (можно приватный), в Settings → Secrets добавь `TG_TOKEN`, `TG_CHAT_ID`, `ALTEGIO_TOKEN`, в Variables — `STAFF_IDS`. Workflow `.github/workflows/check.yml` запускается каждый час, вручную — кнопкой Run workflow. Учти: cron в Actions может опаздывать на 5–15 минут.

**Свой сервер / ноут:**
```bash
go build -o court-watcher .
crontab -e
# */15 * * * * cd /path/court-watcher && STAFF_IDS=123,456 TG_TOKEN=... TG_CHAT_ID=... ./court-watcher >> watcher.log 2>&1
```

## Про ALTEGIO_TOKEN

Токен из виджета — это **статический партнёрский ключ**, зашитый в сборку публичного JS
(`apiToken` в бандле виджета, переопределяется только параметром `?api_key=` в URL).
Он один и тот же для всех посетителей и не привязан ни к кукам, ни к логину, так что
от прогона к прогону не сгорает. Сессионный токен пользователя в виджете тоже есть, но
эндпоинты слотов (`book_staff`, `book_dates`, `book_times`) его не требуют.

Меняется он только если Altegio пересоберёт виджет или ротирует ключ. Молчаливой поломки
не будет: на `401`/`403` бот присылает в Telegram «не принимает ALTEGIO_TOKEN» — один раз,
а не каждый час. После обновления токена в secrets алерт сбросится сам на первом удачном прогоне.

Чтобы заранее понять, истекает ли твой токен: если он выглядит как JWT (три блока через точки) —
внутри есть срок жизни `exp`; если это просто непрозрачная строка — срока нет.

### Запас перед началом

`BOOK_MIN_LEAD=5` — не бронировать, если до начала слота осталось меньше 5 часов.

Считается вычитанием, но в поясе клуба (`TZ_OFFSET=5`, Asia/Almaty), а не в UTC
раннера. Сравнение по UTC ошибается на 5 часов и ломает фильтр в опасную сторону:
при времени 19:18 в Алматы (до 22:00 — 2ч42м) версия с UTC считает, что запас
7ч42м, и бронь проходит. Замерено:

```
TZ_OFFSET=5  -> подходящих 10 из 14, отсеяно по запасу <3ч: 4
TZ_OFFSET=0  -> подходящих 14 из 14, отсеяно: 0
```

## Переменные

| Переменная | По умолчанию | Что это |
|---|---|---|
| `COMPANY_ID` | `521176` | id филиала |
| `API_BASE` | `https://api.alteg.io/api/v1` | база API из DevTools |
| `ALTEGIO_TOKEN` | — | Bearer из запросов виджета |
| `STAFF_IDS` | — | id крытых кортов |
| `NAME_FILTER` | `крыт,indoor,хард` | поиск кортов по имени |
| `DAYS_AHEAD` | `7` | горизонт в днях |
| `TG_TOKEN`, `TG_CHAT_ID` | — | Telegram |
| `STATE_FILE` | `state.json` | память об отправленном |
